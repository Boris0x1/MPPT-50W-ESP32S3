MPPT 50 W - REPRODUCIBILITY

This folder accompanies the published simulation and firmware sources.
It contains instructions, fixed configurations, input profiles, integrity
checks and software replay tests. It does not contain new experimental data.

1. REPOSITORY LAYOUT

Extract this package so that reproducibilidad is next to simulacion, datos
and firmware:

  simulacion/modelos/                 three published SLX models
  simulacion/nucleos_simulink/        three archived MATLAB kernels
  simulacion/algoritmos/              seven named MATLAB entry functions
  firmware/MPPT_ESP32-S3_7_algoritmos/             latest, renamed seven-controller firmware
  datos/                             original experimental CSV files
  reproducibilidad/                  this package

Keep the file names and directories from SIMULINK_Y_CODIGOS_MATLAB.zip.
The latest firmware is MPPT_ESP32S3_7_ALGORITMOS_NOMBRES_CORREGIDOS.zip.
Do not mix its renamed headers with earlier firmware sources.
The experimental CSV files may be nested under datos. Preserve their contents.
Do not upload the new results generated by the tests as original acquisitions.

2. REQUIREMENTS AND RECORDED ENVIRONMENTS

File checks: Python 3, standard library only.
MATLAB controller replay: MATLAB; no Simulink plant run is required.
Recorded recent replay environment: R2026a Update 5.
Switched-plant models: the original study environment was MATLAB/Simulink
R2024b Update 10 with Simscape Electrical Specialized Power Systems and
support for MATLAB Function blocks. Use the original environment to compare
plant results; successful controller replay in another release does not
establish plant-model compatibility or identical solver results.
C controller replay: GCC on PATH and Python 3, standard library only.
The recorded host compiler was GCC 13.2.0 (MinGW-W64, 64 bit).
Full target compilation/flashing additionally requires an appropriate
ESP-IDF environment; it is not performed by the host replay test.

3. VERIFY FILE IDENTITY FIRST

From the repository root:

  python reproducibilidad/pruebas/comprobar_integridad.py

To check just the simulation package and these supporting files:

  python reproducibilidad/pruebas/comprobar_integridad.py --solo-simulacion

Use --repo PATH when the repository is stored elsewhere.
The report is written to reproducibilidad/resultados/integridad.json.
PASS means byte identity with the supplied reference, not physical validation.
NOT_AVAILABLE identifies optional firmware/data files that were not supplied
at the expected location. MISSING or MISMATCH require reviewing the indicated
file. Keep one authoritative copy of the X1/X3 trace CSV under datos.

4. REPLAY THE SEVEN MATLAB CONTROLLERS

In MATLAB, make the repository root the current folder, then run:

  addpath('reproducibilidad/pruebas');
  verificar_algoritmos;

This compares the seven named functions with their archived kernels using
the same Vpv/Ipv sequences. It checks duty, step, hold, six diagnostics,
limits, reset and the original handling of invalid samples.
When the original X1/X3 trace CSV exists under datos, its eight measured V/I
pairs are replayed in addition to six deterministic software scenarios.
The full input set has 98 cases and 434098 updates across seven controllers.
Without that CSV, six software-only cases per controller are used and the
report explicitly records zero experimental trace rows.
Software test signals are not experimental measurements or plant simulations.

Outputs:
  resultados/equivalencia_matlab.json
  resultados/oraculo.bin
  resultados/casos.json

The binary is a temporary reference replay vector for the C test. It can be
regenerated; it is not an acquisition file. All original inputs remain intact.

5. REPLAY THE RECEIVED C CONTROLLERS

After step 4, from the repository root:

  python reproducibilidad/pruebas/verificar_firmware.py

This compiles the received portable MPPT component and the common control
stage on the computer. It includes the quietWindow linker replacement used
by the application. It compares the same nine outputs with the MATLAB oracle
and exercises all seven public init/update/reset interfaces, independent
states, invalid inputs, serial-mode mapping and PWM comparison limits.
It expects the latest firmware hashes recorded in FIRMWARE_SHA256.json.
It does not compile ESP-IDF peripherals, flash a board or verify real deadlines.

Outputs:
  resultados/equivalencia_firmware.json
  resultados/compilacion_host.log

For an alternate repository location, set the environment variable
MPPT_REPO_ROOT before invoking this Python script. Use the same repository
that supplied the MATLAB replay vector.

6. PREPARE A SWITCHED-PLANT CASE WITHOUT STARTING A SIMULATION

In MATLAB R2024b with the required toolboxes, from the repository root:

  addpath('reproducibilidad/scripts');
  preparar_simulacion('adaptive_meng_with_probing_mppt', ...
                     'X1_escalones_y_carga');

The adapter copies the selected SLX into resultados/modelos_trabajo, injects
the exact archived kernel and applies the fixed configuration for that
controller. It prepares the original input profile and opens the working
copy. It does not start the simulation and does not modify published files.
Close an already open model with the same name before selecting another case.

Controller identifiers:
  po_mppt
  inc_mppt
  meng_vi_mppt
  adaptive_meng_mppt
  po_with_probing_mppt
  adaptive_meng_with_probing_mppt
  adaptive_meng_without_probing_mppt

Main numerical profiles:
  E1_escalones_articulo, E2_rampa20_articulo, E3_rampa50_articulo,
  U2_rampa, PSC_fuerte, PSC_moderado, PSC_dinamico,
  X1_escalones_y_carga, X3_lobulo_remoto, X5_lobulos_secundarios.

R9 is also available from its fixed, archived definition. Do not redraw it
or tune controllers on it. Archived R9 results correspond to the controller
entries actually listed in referencias/resultados_R9_archivados.json.
Preparing any other entry on R9 would be a new case, not an archived result.

7. RUN A NEW NUMERICAL CASE ONLY WHEN NEEDED

  metricas = ejecutar_caso('adaptive_meng_with_probing_mppt', ...
                          'X1_escalones_y_carga');

This explicitly starts the switched-plant simulation. It stores time, logged
signals, the external GMPP reference and energy metrics in a new timestamped
MAT file under resultados/simulaciones. It integrates Ppv and the reference
over the same time vector using the trapezoidal rule:

  eta_E = 100 * trapz(t,Ppv) / trapz(t,PGMPP).

No old MAT or experimental CSV is overwritten. The adapter uses normal
simulation mode, the archived 2 us electrical step, 1 ms averaging and
2 ms acquisition. Runtime can differ from the accelerated historical runs.

8. FIXED PARAMETERS AND MECHANISM IDENTITY

The full 15-element vectors are in configuracion/PARAMETROS_CONTROLADORES.json.
All cases use Vpv [V], Ipv [A] and local time [s]. No measured irradiance,
temperature or output-side quantity is an MPPT decision input.
The nameplate constants are Vm=18.25 V and Im=2.74 A, about 50 W.
Initial duty is 0.4; the core bounds are [0,716/1024], with local search
enabled after 20 ms. The update period is 2 ms.
P&O/INC use h=0.004. Adaptive Meng uses kappa=0.032; Adaptive Meng with
probing uses kappa=0.024 and the final accelerated directional return.
P&O with probing retains its archived local step of 0.002.
The no-periodic-probing variant changes only cfg(10) from 1 to 0. Recovery
and full global audits remain enabled. It is not an ablation of all exploration.
The simulated 10-bit PWM convention and the firmware native MCPWM mapping
are distinct stages; the host checks do not measure physical PWM resolution.

9. EVIDENCE AND SCOPE

evidencias contains archived reports and the results of testing this package.
referencias preserves tuning selections, the final-code closure, numerical
summaries, ablations and the additional R9 result, including adverse cases.
Historical names/paths inside copied records are provenance metadata; the
current display names are in configuracion/INDICE_ALGORITMOS.csv.

The ten main profiles participated in development. They are not independent
external validation of the final controller. The comparable initial scalar
selection and the later accelerated-return development remain distinct.
The records do not establish universal superiority or equal total historical
development effort. R9 was an additional check after closure, not a tuning set.

This compact package supports file checks, controller replay and fixed-case
plant execution. It does not bundle every historical MAT trace or automatically
rebuild every table/figure of the article. Full historical table audits also
require the corresponding numerical result archives in datos. Experimental
measurements, physical timing/calibration and any acquisition provenance are
not established by software replay alone.

The original models, controller logic, gains and measured CSV files were not
edited when preparing this package. Newly generated outputs are excluded by
the local .gitignore. Copy only the package files to reproducibilidad on GitHub.
